# Contributing translations

[简体中文](./i18n.md)

SQL Mother defaults to Simplified Chinese and includes an English interface and translations of all 45 active lessons. Use the language selector in the header. Your preference is saved locally; switching languages preserves your SQL, query results, and playground database.

## Where translations live

- `src/i18n/messages/zh-CN.ts`: source UI messages and message keys.
- `src/i18n/messages/en.ts`: English UI messages.
- `src/i18n/index.ts`: language registry, current language, storage, and `t()`.
- `src/i18n/lessons.ts`: Vite imports for translated lesson titles, content, and hints.
- `src/levels/main/level1/locales/en.md`: translated lesson content.
- `src/levels/main/level1/locales/en.json`: translated title and hint.

The original `README.md`, `index.ts`, and `createTable.sql` remain the sources for Chinese lessons and executable exercises. Display components resolve translations while the editor keeps the original lesson object, so switching languages does not reset its database.

## Add a language

For example, to add French (`fr`):

1. Copy `src/i18n/messages/en.ts` to `fr.ts` and translate the values. Keep the keys and interpolation names such as `{error}`. Keep the `Record<keyof typeof zhCN, string>` type so missing messages are caught by TypeScript. Rename the exported variable; no new package is needed.
2. Import the catalog in `src/i18n/index.ts`, add `fr` to `messages`, and add `{ code: "fr", label: "Français" }` to `locales`. Use the language's own name in the selector.
3. In `src/App.vue`, import the existing Ant Design Vue locale `ant-design-vue/es/locale/fr_FR` and add it to `antdLocales`. The document title, description, keywords, and HTML `lang` update automatically.
4. Add `fr.md` and `fr.json` inside each lesson's `locales` directory. Vite discovers these automatically; no changes to the lesson registry are necessary. This works for both core and community lessons.

Metadata format:

```json
{
  "title": "Translated lesson title",
  "hint": "Translated hint"
}
```

Omit `hint` if the source lesson has none. Missing or empty titles, content, and hints fall back individually to their original Chinese values. Languages can be contributed incrementally; describe the coverage in your pull request. Translations currently use static imports, matching the original course-loading approach.

## Translation guidelines

- Translate the complete tutorial, example explanations, exercise requirements, and hints. Preserve Markdown tables and code blocks.
- Keep SQL table names, column names, aliases, and string values unchanged. For example, explain that `男` means male, but keep `gender = '男'`; changing it to `gender = 'male'` would query different data. Required Chinese column aliases must also remain unchanged.
- Preserve names and categories in example tables so queries and results still match. SQL comments may be translated.
- Do not change `initSQL`, `defaultSQL`, `answer`, lesson keys, or grading behavior as part of a translation. The original SQL displayed in the editor and database values may contain Chinese; these are part of the exercise data.
- State required output column names and order, filters, sorting, and row limits clearly. Report source inconsistencies in your pull request instead of silently changing reference answers.
- Preserve Yupi's attribution, the original project links, and author resources. No live translation service, API key, or backend is required.

## Verify your contribution

```bash
npm ci
npm test
npm run build
```

Tests use Node's built-in test runner (Node 18+) and the existing Vite and sql.js packages. They check UI keys and interpolation, language persistence, blocked storage, English coverage for 45 lessons, Chinese fallback, unchanged source lessons, and execution of every reference answer.

Also check the browser: changing languages preserves the query, results, selected lesson, and expanded hints; reloading restores the selected language; data created or changed in the playground remains queryable; the lesson list, author dialog, error messages, and narrow layouts work correctly.

The original project has `vue-tsc --noEmit` diagnostics because the playground omits required `resultStatus` props. This translation contribution keeps those existing component interfaces. Production builds also retain pre-existing nested-CSS and large-chunk warnings.
